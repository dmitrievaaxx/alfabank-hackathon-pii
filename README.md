## Контекст

В Альфа-Банке работают ИИ-ассистенты и агенты, которые помогают клиентам решать задачи — от консультации по карточным продуктам до планирования инвестиционной стратегии. В рамках этих сценариев в запросы к LLM неизбежно попадают персональные данные: ФИО, дата рождения, паспорт, номер карты, телефон и другие.

**Проблема:** передача ПДн во внешние языковые модели нарушает **ФЗ-152 «О персональных данных»** и несёт юридические риски для банка.

---

## Решение

Прокси-слой между пользователем и LLM, который в реальном времени:

1. **Обнаруживает** персональные данные в тексте запроса (NER-модель, без LLM)
2. **Маскирует** их токенами-заглушками `[ФИО_1]`, `[ТЕЛЕФОН_1]` и т.д.
3. **Отправляет** маскированный запрос в LLM
4. **Восстанавливает** оригинальные значения в стриминговом ответе на лету

Пользователь видит полноценный ответ с реальными данными — LLM никогда не получает ПДн.

## Результаты (Задача 1 — NER)

Модель обучена на данных соревнования Kaggle (`llm-march2026-alfabank`).

| Метрика | Значение |
|---|---|
| **F1-score (micro, submission)** | **0.97254** |
| Схема разметки | BIO (61 метка) |
| Количество категорий ПДн | 30 |
| Базовая модель | `DeepPavlov/rubert-base-cased-conversational` |
| Обучающая выборка | 7 458 примеров |
| Валидационная выборка | 829 примеров |

Оценка по строгому совпадению границ и категории (strict span + category match, micro-averaged F1).

Веса дообученной модели опубликованы на HuggingFace: [dancessa/ner-alpha-bank](https://huggingface.co/dancessa/ner-alpha-bank)

```
┌──────────────────────────────────────────────────────────┐
│                   PII Proxy  (FastAPI)                   │
│                                                          │
│  ┌──────────────────┐     ┌───────────────────────────┐  │
│  │   NER-модель     │     │    Модуль маскирования    │  │
│  │  rubert-base     │────►│  mask_text / restore_text │  │
│  │ (fine-tuned)     │     │  vault: токен → значение  │  │
│  └──────────────────┘     └──────────────┬────────────┘  │
│                                          │               │
│                                          ▼               │
│                             ┌────────────────────────┐   │
│                             │    OpenRouter API      │   │
│                             │    (SSE streaming)     │   │
│                             └────────────────────────┘   │
└──────────────────────────────────────────────────────────┘
                      │  SSE-стрим (восстановленный текст)
                      ▼
                   Клиент
```

### Ключевые принципы

- **Без LLM для детекции** — NER-модель работает локально, без внешних API-вызовов
- **Real-time** — ответ стримится через SSE, маски восстанавливаются накопительно по мере поступления токенов
- **Безопасность** — vault с оригинальными значениями живёт только в памяти одного запроса, не логируется
- **Масштабируемость** — добавление новой категории ПДн = одна строка в `labels.py`

## Запуск

### 1. Создать `.env` в корне проекта

```env
OPENROUTER_API_KEY=sk-or-...
OPENROUTER_MODEL=openai/gpt-4o-mini
```

### 2. Собрать и запустить

```bash
docker compose up --build -d
```

> При первом запуске NER-модель (~700 МБ) скачивается с HuggingFace автоматически и кешируется в Docker volume — повторные запуски мгновенные.

### 3. Открыть интерфейс

```
http://localhost:8000
```

### Остановить

```bash
docker compose down
```

### Пересобрать после изменений в коде

```bash
docker compose down && docker compose build && docker compose up -d
```
